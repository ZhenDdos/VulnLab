# SQLI-001 — SQL-инъекция в сортировке каталога

- **CWE:** 89 — Improper Neutralization of Special Elements used in an SQL Command
- **Маршрут:** `GET /api/products`
- **Параметр:** `sortBy`
- **Доступ:** маршрут требует аутентификации
- **Статус:** исправлено в `fix/sqli-001`; уязвимый пример оставлен в `lab/sqli-001`

## Причина

В лабораторном варианте значение `sortBy` из query string напрямую
конкатенировалось в SQL-выражение `ORDER BY`. Значение не ограничивалось
разрешённым набором до выполнения запроса. Custom rule Semgrep помогла найти
этот поток данных ([правило в `lab/sqli-001`](https://github.com/ZhenDdos/VulnLab/blob/lab/sqli-001/.semgrep/rules/sql-injection.yml));
динамическая проверка проводилась только локально на учебных данных.
Проверочные запросы и данные из БД здесь не публикуются.

## Оценка риска

Риск зависит от прав PostgreSQL и доступности маршрута. Поскольку endpoint
требует аутентификации, это ограничивает круг потенциальных пользователей, но
не устраняет проблему.

## Исправление

Приложение принимает ожидаемое направление сортировки и подставляет в SQL
только фиксированный токен `ASC` или `DESC`. Параметры запроса не могут
подставлять SQL-идентификаторы или ключевые слова, поэтому для сортировки
используется allowlist, а не прямая интерполяция пользовательского значения.

## Проверка

`npm test` проверяет допустимые направления и безопасное поведение для
неожиданных типов и значений. Quality workflow запускает эти тесты и сборку
backend. Повторный запуск custom Semgrep rule на исправленном варианте должен
подтверждать отсутствие этого потока.
