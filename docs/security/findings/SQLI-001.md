# SQL-инъекция в сортировке каталога

- **Идентификатор:** SQLI-001
- **Статус:** Исправлено
- **Маршрут:** `GET /api/products`
- **Параметр:** `sortBy`
- **Классификация:** CWE-89 — Improper Neutralization of Special Elements used in an SQL Command
- **Серьёзность:** предварительно High; требует оценки с учётом привилегий роли базы данных и доступности данных

## Обнаружение

Уязвимость была обнаружена засчет правило Semgrep: [.semgrep/rules/sql-injection.yml](../../../.semgrep/rules/sql-injection.yml)

## Описание

Маршрут получает `sortBy` из query string и вставляет значение непосредственно
в SQL-выражение `ORDER BY`. Значение не ограничивается набором разрешённых
направлений сортировки до выполнения запроса.

Уязвимый участок: [`backend/src/routes/products.ts`](../../../backend/src/routes/products.ts).
Маршрут подключён с `authMiddleware`, поэтому для обращения к нему требуется
аутентификация.

## Подтверждение

Время ответа API
зависело от условия, переданного через `sortBy`. Это согласуется с time-based
SQL-инъекцией. Проверка выполнялась локально на учебных данных; строка проверки
и данные из базы в отчёт не включены.

Пример запроса: desc, CASE WHEN (SELECT SUBSTRING(email,1,1) FROM users ORDER BY id LIMIT 1)='z' THEN pg_sleep(5)::text ELSE '' END --

## Возможное влияние

Аутентифицированный пользователь может влиять на SQL, выполняемый приложением.
Фактическое воздействие ограничено правами учётной записи PostgreSQL и
доступностью маршрута.

## Рекомендация

Разрешать только ожидаемые значения направления сортировки и выбирать
соответствующий заранее заданный SQL-фрагмент. Не подставлять произвольное
значение query-параметра в SQL. Для неизвестных значений возвращать ошибку
валидации либо использовать документированное безопасное значение по умолчанию.
Параметризацию использовать для значений запроса; SQL-ключевые слова выбирать
только из allowlist.
