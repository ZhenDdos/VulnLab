# Результаты Semgrep

Дата проверки: 2026-11-12

Команда:

```powershell
semgrep scan --config p/owasp-top-ten --config p/nodejs backend frontend
```

## `dockerfile.security.missing-user`

**Статус:** подтверждённое замечание по наименьшим привилегиям.

**Файлы:** `backend/Dockerfile`, `frontend/Dockerfile`.

В обоих Dockerfile не задан непривилегированный пользователь. Образ
`node:20-alpine` по умолчанию запускает процесс от `root`, поэтому
`npm run dev` работает с правами root внутри контейнера. Это может увеличить
последствия компрометации приложения внутри контейнера, но само по себе не
означает получение root-доступа на хосте.

**Рекомендация:** запускать приложение от непривилегированного пользователя
(например, `node`) и проверить, что у него есть необходимые права на файлы и
каталоги приложения.

## `javascript.express.session-fixation`

**Статус:** вероятное ложное срабатывание для текущего кода.

**Файл:** `backend/src/routes/auth.ts`.

В обработчике входа cookie получает JWT, который сервер подписывает через
`jwt.sign` после успешной проверки пароля. Значение cookie не копируется из
переданного клиентом cookie или другого значения сессии из запроса. Поэтому
срабатывание правила о передаче управляемых запросом данных в `res.cookie`
не подтверждается этим кодовым потоком.

## `javascript.express.web.cookies-secure-false-express`

**Статус:** контекстный риск; настройка допустима только для ограниченного
локального сценария.

**Файл:** `backend/src/routes/auth.ts`.

При `secure: false` браузер может отправлять cookie по HTTP. Если такой трафик
проходит по недоверенной сети, cookie может быть перехвачена. `httpOnly` не
защищает от перехвата сетевого трафика.
